# divergences.txt - where the q analysis deliberately differs from the
# Scala one: the type checker (parts 1-3) and the join analysis (part 4).
# Each block replaces the block with the same "===" line in a golden file
# (expr_golden.txt, the program goldens, join_golden.txt), and says what q
# prints instead.
# Lines starting with # are comments; a blank line ends a block.

# 1. CASE with two or more WHEN branches. Scala checks the later branches
#    as whole IfThen nodes instead of their THEN expressions and crashes
#    with scala.MatchError (also under aquery.jar -tc on a whole program).
#    q checks their THENs against the first THEN's type, as Scala meant.
=== expr	CASE WHEN x THEN 1 WHEN y THEN "a" END
TYPE	numeric
ERROR	Type Error: expected numeric found string at [1,32]

=== expr	CASE 1 WHEN 2 THEN "a" WHEN 3 THEN "b" ELSE "c" END
TYPE	string

=== expr	CASE WHEN x THEN 1 WHEN y THEN 2 END
TYPE	numeric

# 2. The position of * and ROWID. Scala's * and ROWID are single shared
#    objects that keep the position of the first one ever parsed, so their
#    position in an error is not reliable. The q tree gives them no
#    position, so q reports the position of the nearest enclosing node
#    that has one, or [0,0] if there is none.
=== expr	ROWID
TYPE	numeric
PROHIBITED	Expr Error: Illegal expression in ROWID at [0,0]

=== expr	f(ROWID)
TYPE	unknown
PROHIBITED	Expr Error: Illegal expression in ROWID at [1,1]

# 3. Statements Scala has no case for (it crashes with scala.MatchError).
#    q: LOAD, SAVE and DROP TRIGGER have no errors; CREATE TRIGGER checks
#    the statement after DO, with the REFERENCING names (here ins) usable
#    as t in t.c. The errors on line 18 are what Scala reports for that
#    UPDATE on its own.
=== program	tests/analysis/stmt_crash_cases.a
ERROR	Type Error: expected numeric found string at [18,32]
ERROR	Table Error: Unknown correlation name in q.id at [18,42]
ERROR	Type Error: expected boolean found numeric at [18,55]
ERROR	Type Error: expected boolean found numeric at [22,23]

# 4. Placing a WHERE condition in a join (join_golden.txt, version 7).
#    Scala's placeFilter has two bugs, which q fixes:
#    - a condition naming a table that is not in the FROM clause (zz.c2,
#      or t1.c1 when t1 is only known by its alias) is placed nowhere, so
#      it disappears from the query. q places it on top of the join, as
#      for a plain column, so it is kept.
#    - a condition with no columns (1 = 1) is copied onto every table.
#      q places it once, on top of the join.
=== place	t1, t2	1 = 1
Filter #1	avail=t1 t2
  Join Cross	avail=t1 t2
    Table t1	avail=t1
    Table t2	avail=t2

=== place	t1, t2	zz.c2 > 1
Filter #1	avail=t1 t2
  Join Cross	avail=t1 t2
    Table t1	avail=t1
    Table t2	avail=t2

=== place	t1 AS a, t2 AS b	a.c1 = b.c1 ; t1.c1 > 0
Filter #1	avail=a b
  Filter #2	avail=a b
    Join Cross	avail=a b
      Table t1 AS a	avail=a
      Table t2 AS b	avail=b
